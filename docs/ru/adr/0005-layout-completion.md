# ADR-0005: Завершение 1D Flexbox-разметки

## Статус
Принято

## Контекст
ADR-0001 выбрал 1D flexbox-движок разметки, но не реализовал его.
Нам нужно было поставить пакет, чтобы приложения могли сразу строить
деревья компонентов, сохраняя контракт нулевых аллокаций из
AGENTS.md §7.

## Решение
Пакет `layout` реализует типы `Container`, `Leaf` и `Child` согласно
ADR-0001, с тремя целочисленными свойствами разметки (`Basis`,
`Grow`, `Shrink`) и двумя направлениями (`Row`, `Column`).

Три алгоритмических правила управляют распределением:

1. **Фаза 1 — Basis**: каждый ребёнок с `Basis > 0` получает ровно
   столько на главной оси; остаток суммируется.
2. **Фаза 2 — Grow / Shrink**: свободное место делится по `Grow`,
   переполнение поглощается по `Shrink`. Остаток целочисленного
   округления распределяется по одной единице первым подходящим
   детям.
3. **Фаза 3 — Раскладка**: каждый ребёнок располагается по главной
   оси; последний ребёнок поглощает остаток округления, чтобы
   `sum(child main sizes) == available`.

Нулевая аллокация требует стек-аллоцированного scratch-буфера на
контейнер для размеров детей. Буфер вмещает 256 записей; более
широкие контейнеры откатываются к одноразовой куче-аллокации в
`measureSlow`. Размер по поперечной оси передаётся без изменений
(дети Row получают высоту родителя; дети Column получают ширину
родителя).

## Обоснование

- Ментальная модель CSS flexbox минимизирует порог входа для новых
  контрибьюторов.
- Трёхфазный алгоритм — O(N) на контейнер и тривиально проверяется
  вручную.
- Предварительное выделение результирующего слайса и протягивание
  его через рекурсию сохраняет горячий путь 0 B/op, 0 allocs/op
  (проверено benchmark'ом).

## Последствия

- Многоосные сетки требуют вложенности (Row → Column → Row …) — тот
  же trade-off, который спека уже приняла.
- `measureSlow` аллоцирует один раз для контейнеров шире 256
  детей; на практике на TUI-дереве это никогда не срабатывает.
- Поле `Child.Node` опционально; `nil` порождает layout rect без
  рекурсии.
